# 直播订阅 · 手机端应用

一个手机端可用的直播订阅提醒应用，支持 **B站** 和 **抖音** 主播开播检测与提醒。
无需安装 App，手机浏览器打开即用，可"添加到主屏幕"变成独立应用（PWA）。

## 功能特性

- 订阅 B站 / 抖音 直播间，支持多种输入方式（完整链接、房间号、抖音短链、抖音号）
- 每 60 秒自动检测一次开播状态（多个订阅间隔 2 秒，规避平台风控）
- **三级递进提醒**：
  - 第 1 级（开播瞬间）：系统通知 + 顶部悬浮横幅
  - 第 2 级（30 秒）：横幅持续显示，可"去观看 / 已收到 / 稍后"
  - 第 3 级（60 秒）：横幅常驻 + 循环提示音 + 呼吸闪烁
- 免打扰时段设置、声音开关、备注名、实时状态列表

## 快速开始

### 方式 A：部署到免费托管（推荐，不依赖电脑）

把应用部署到免费云平台，手机随时随地访问，不依赖电脑开机。订阅数据保存在手机浏览器本地（localStorage），服务端重启/休眠也不会丢失。

推荐平台：**Render**（免费、无需信用卡、支持 Docker）。

#### 部署到 Render 步骤

1. **准备 GitHub 仓库**：把 `live-sub-app` 文件夹推到一个公开的 GitHub 仓库（需要先注册 GitHub 账号）。
   ```bash
   cd live-sub-app
   git init
   git add .
   git commit -m "live-sub-app"
   git remote add origin https://github.com/<你的用户名>/live-sub-app.git
   git push -u origin main
   ```

2. **在 Render 创建服务**：
   - 打开 https://render.com 注册登录（免费，无需信用卡）
   - 点 **New + → Blueprint**（蓝图），选择你的 GitHub 仓库
   - Render 会自动读取仓库里的 `render.yaml`，创建名为 `live-sub-app` 的免费 Web 服务
   - 点 **Apply** 开始部署，等 2~5 分钟构建完成

3. **获取网址**：部署完成后，服务会分配一个 `https://live-sub-app-xxxx.onrender.com` 的 HTTPS 地址。手机打开这个网址即可使用，还能正常使用系统通知（HTTPS 环境）。

> 免费版说明：Render 免费服务在 15 分钟无访问后会自动休眠，手机页面打开时每 2 分钟会自动刷新一次，因此页面开着就不会休眠；关闭页面后服务休眠，再次打开会自动唤醒（约 1 分钟）。

#### 备选平台：Koyeb

Koyeb 也有免费套餐（512MB 内存、无需信用卡），支持从 GitHub 或 Docker 部署，休眠策略更宽松。在 https://koyeb.com 创建账号后，选择 **Create Web Service → GitHub**，指向你的仓库即可（它会自动识别 Dockerfile）。

### 方式 B：本地运行（需要电脑）

需要 Node.js 14+（推荐 18+）。

```bash
cd live-sub-app
npm start
# 或直接：node server.js
```

启动后终端会显示：

```
📡 直播订阅服务已启动
   本机访问:   http://localhost:3000
   手机访问:   http://<本机局域网IP>:3000
```

### 2. 手机访问

确保手机和电脑连接**同一个 WiFi**，然后在手机浏览器打开：

```
http://<电脑的局域网IP>:3000
```

> 电脑局域网 IP 查看方式：Windows 用 `ipconfig`，Mac 用 `ifconfig` 或系统设置里查看。
> 若手机打不开，请检查电脑防火墙是否放行 3000 端口。

### 3. 添加到主屏幕（可选，推荐）

- **iPhone（Safari）**：点分享按钮 → "添加到主屏幕"
- **安卓（Chrome/Edge）**：菜单 → "添加到主屏幕" / "安装应用"

添加后即可像普通 App 一样从桌面图标打开，全屏显示。

## 使用方法

### 添加订阅

在"添加订阅"卡片中，支持以下输入：

| 输入方式 | 示例 |
| --- | --- |
| B站直播间链接 | `https://live.bilibili.com/12345` |
| B站房间号（纯数字） | `12345` |
| 抖音直播间链接 | `https://live.douyin.com/123456789012` |
| 抖音短链 | `https://v.douyin.com/xxxxxx/` |
| 抖音用户主页 | `https://www.douyin.com/user/xxx` |
| 抖音号 | `某主播的抖音号` |

### 提醒设置

- **开播声音提醒**：开关提示音
- **免打扰时段**：设置时间段，期间不弹开播提醒（支持跨天，如 23:00 ~ 07:00）
- **系统通知**：点击"开启通知"授权后，开播时在手机通知栏弹出提醒（需 HTTPS 或 localhost 环境才可用）

### 管理订阅

- 列表按直播状态排序，直播中的主播显示"直播中"红点
- 点击 ✎ 可设置备注名，点击 ✕ 可取消订阅
- "立即检查"按钮可手动触发一次状态检测

## 三级递进提醒说明

| 层级 | 触发时间 | 表现 |
| --- | --- | --- |
| 第 1 级 | 检测到开播瞬间 | 系统通知 + 顶部悬浮横幅（15 秒倒计时） |
| 第 2 级 | 30 秒后未处理 | 横幅保持，可"去观看 / 已收到 / 稍后" |
| 第 3 级 | 60 秒后仍未处理 | 横幅常驻 + 循环提示音 + 呼吸闪烁 |

点"去观看"直接跳转直播间，点"已收到"或"稍后"可关闭横幅。

## 常见问题

**Q：手机打不开页面？**
A：本地运行时，确认手机和电脑在同一 WiFi，检查电脑防火墙是否放行 3000 端口。部署到免费托管后，直接用 HTTPS 网址访问即可，无此问题。

**Q：系统通知不弹？**
A：系统通知需要 HTTPS 环境（或 localhost）。本地通过局域网 IP 访问属于 HTTP，部分浏览器会限制通知权限，此时可依赖悬浮横幅 + 声音提醒。部署到 Render/Koyeb 后自带 HTTPS，系统通知即可正常使用。

**Q：订阅数据会丢吗？**
A：不会。订阅列表保存在手机浏览器本地（localStorage），服务端重启/休眠后，重新打开页面会自动把订阅同步给服务端。注意：同一部手机上的订阅不会自动同步到另一部手机（各设备独立）。

**Q：检测不到某主播开播？**
A：抖音链接解析偶尔会失败，可尝试直接输入直播间链接或房间号；B站房间号可直接输入数字。

**Q：想改检测频率？**
A：启动时设置环境变量，如 `LIVE_POLL_MS=30000 node server.js`（改为 30 秒）。免费托管上默认 60 秒即可。

## 项目结构

```
live-sub-app/
├── server.js          # 后端服务（纯 Node，无第三方依赖）
├── package.json       # 项目配置
├── Dockerfile         # 免费托管用的 Docker 镜像配置
├── render.yaml        # Render 一键部署配置（Blueprint）
├── .dockerignore      # Docker 构建忽略文件
├── live_subs.json     # 服务端缓存（订阅以手机本地为准）
└── public/
    ├── index.html     # 手机端页面（UI + 三级提醒逻辑）
    ├── manifest.json  # PWA 配置
    ├── sw.js          # Service Worker（离线缓存）
    └── icon.svg       # 应用图标
```

## 技术说明

- 后端：Node.js 内置模块，无任何第三方依赖，`node server.js` 即可运行
- 实时推送：SSE（Server-Sent Events），服务端检测到状态变化即时推给前端
- 状态检测：B站走官方 API，抖音解析直播间页面
- 前端：原生 HTML/CSS/JS，移动端优先，支持 PWA 安装
- 数据持久化：订阅保存在手机浏览器 localStorage（客户端权威模式），服务端仅作轮询与推送，天然适配免费托管的临时文件系统
